
# Application architecture

`src/geoanalysis/ui/app.py` is the Streamlit entry point. Folium renders an Esri World Imagery tile layer with attribution and Leaflet.Draw controls. `streamlit-folium` returns `all_drawings` as GeoJSON Features after drawing, editing, and deletion.

The entry point adds the absolute `src` directory to both `sys.path` and `PYTHONPATH`, preserving existing environment entries. Streamlit's imported-module watcher uses `PYTHONPATH`, not arbitrary additions to `sys.path`, when deciding whether sibling backend files should be watched. This allows changes in `core`, `services`, and `analysis` to invalidate cached modules on rerun. Servers launched before this registration need a one-time restart; no forced per-rerun module reload is used.

The map and AOI confirmation panel run together in a Streamlit fragment so map interactions do not rerun the surrounding page. The component returns its center, zoom, and drawing collection; an on-change callback stores them before rerendering. Center and zoom are passed through the component's dynamic viewport arguments. An empty drawing list clears the selection; a `None` response during initialization does not replace it or reset the saved viewport.

The map script and component key remain stable as selection/viewport data change. Recovery data is serialized separately in the HTML; on an iframe remount, a Folium macro restores the last center/zoom and repopulates the actual editable Leaflet.Draw feature group. It does not add duplicate display-only polygons during normal reruns. The explicit clear button resets the drawings and changes the component key while retaining the current location.

The persistent **Your AOI & GeoJSON** panel sits next to the map. Valid boundaries show a success confirmation, a download button, and an expanded copyable JSON preview. A download is a user-initiated browser file transfer named `pet-project-aoi.geojson`; the application does not automatically write an AOI file to the repository. Selection and viewport recovery are limited to the active Streamlit session, not permanent storage across browser refreshes or server restarts.

Optional Esri World Boundaries and Places and World Transportation reference tile layers supply city labels, administrative boundaries, roads, and street names above satellite imagery, below the AOI drawings. Both are enabled by default and independently exposed in a layer control. Folium's Geocoder control submits address/city/place searches directly from the browser to OpenStreetMap Nominatim. The default result handler fits the result bounds and adds a navigation marker; `zoom=None` preserves that fitted view rather than forcing a city-scale zoom on addresses. The marker is outside Leaflet.Draw's feature group and is not included in `all_drawings` or AOI exports. Suggestions while typing are disabled via the suggestion-length threshold. Search attribution is shown below the map. Public deployment must account for Nominatim's shared rate limit and caching requirements or select another geocoding provider.

`core/geometry.py` validates the entire selection before export: polygon-only geometry, closed rings, finite WGS 84 coordinates, no date-line-crossing edges, and valid topology through Shapely. It returns a fresh FeatureCollection without mutating the component's data. Every drawn polygon is exported; selecting one polygon from several or unioning them is outside this phase.

The coordinate form above the map uses `core/geometry.py::parse_coordinates` to validate decimal latitude/longitude pairs, then sets the viewport to zoom 16. Explicit submission increments the component revision to avoid replaying its previous cached viewport; the existing recovery macro restores the editable AOI/building collection or draft at the requested location. Analysis and review state remain untouched. A separate dynamic feature group displays the red navigation point, excluding it from drawings and exports. Normal reruns/panning do not reapply the searched center, and invalid input leaves the prior view unchanged. No geocoding service is called.

The UI never exports a stale validated selection after an invalid drawing. It builds the download from the current validated drawings, and disables export by omitting it when validation fails or the selection is empty. Downloading does not trigger an application rerun.

`services/buildings.py` reads the immutable Microsoft GlobalMLBuildingFootprints 2026-08-13 CSV index, decodes quadkeys, and selects candidate source partitions near the AOI bounds (with a 0.002-degree tile-edge lookup margin). It reads gzipped GeoJSONL using temporary files and bounded streaming; no imagery is downloaded. Only the release index is cached in process memory. There is no separate database or AOI upload. `services/imagery.py` remains a placeholder.

`analysis/analysis.py::find_buildings` accepts a GeoJSON AOI FeatureCollection, validates/unions the AOIs, and filters the source geometries for interior overlap. It returns full matching footprints with normalized-geometry deduplication, count, source/release, and processing statistics. Boundary-only touches are excluded. Limits and interrupted/corrupt downloads raise errors rather than publishing partial counts. Invalid source geometry is skipped and reported. Resource limits and coverage limitations are documented in `PROJECT.md`.

Run Analysis is an explicit UI action. A geometry fingerprint binds session results to the selected AOI. AOI changes clear stale results; map navigation retains them. `feature_group_to_add` dynamically supplies a separate orange footprint layer to streamlit-folium, so adding results does not change the map's script identity, replace its viewport, or add buildings to Leaflet.Draw/AOI export. A completed empty result clears the overlay and is explained as a data-coverage result. The UI catches source errors and lets the user retry.

## Building review workspace

`core/building_review.py` supplies source-to-review copies, Polygon editor parts, validation/reassembly, source refresh reconciliation, and separate existing/planned counts. `building_result` remains the original Microsoft response. `building_review` contains active corrected/planned records with Microsoft/manual provenance; `removed_buildings` tracks deleted source IDs. A single `building_undo` snapshot restores the previous accepted review. Invalid drafts never replace validated counts or downloadable data.

The map mode changes which collection is inside Leaflet.Draw: AOI boundaries in AOI mode, working buildings in Buildings mode. The other collection is rendered as a reference overlay. Mode/status changes use a distinct component key and restore the saved viewport; data changes within a mode keep a stable script identity. The recovery macro styles restored buildings by provenance/status and assigns a UUID, provenance, and selected status to newly created building layers before streamlit-folium reads them. New manual features therefore keep IDs across later edit/delete events. Multipart source buildings are split into Polygon parts carrying a common `review_id`, then reassembled in Python for counts/export.

The map callback routes `all_drawings` to AOI handling or building review validation according to the mode. Building edits never overwrite `session_state.drawings` or invalidate the source result. Source refresh merges prior additions/overrides and removed source IDs; changing an AOI explicitly clears the review workspace. New plans do not require source retrieval. All review state is session-only; the separate building GeoJSON download preserves active records with provenance and existing/planned status.

## Independent OSM building layer

`services/osm_buildings.py` explicitly queries Overpass building ways and building multipolygon relations with full `out geom` output. Split and reversed relation member ways are joined into closed rings, inners are assigned to containing outers, and complete polygons are validated without repair. Members represented by a relation are excluded as separate buildings. Invalid/incomplete records reject the result instead of silently publishing a partial inventory. Network work is bounded as recorded in `PROJECT.md`; no dependencies are added.

`analysis/osm_buildings.py::find_osm_buildings` validates/unions AOIs before network work, enforces local bounds, filters for interior overlap, and deduplicates normalized geometry/source IDs. It returns full, unclipped footprints with OSM attribution/license, original IDs/tags, retrieval time, and source timestamp. No metric calculation uses geographic degrees.

`ui/osm_buildings.py` keeps this optional source independent of Microsoft originals and editable reviews. `osm_building_result` and `osm_building_error` are bound to the AOI; boundary changes/clear invalidate them. Loading and toggling update dynamic feature groups without modifying map identity, viewport, roads, or building edits. The cyan layer never enters Leaflet.Draw. Failed reloads retain and explicitly label the previous result. Counts/downloads remain separate to avoid unsupported cross-source conflation; OSM-to-review import and automatic merging are deferred. Redistribution must preserve OSM attribution and comply with ODbL, including applicable share-alike obligations.

## Independent road layers

`services/roads.py` runs the official Overture client in a subprocess with a 180-second deadline, so client startup/STAC access and cloud scanning cannot block the Streamlit session indefinitely. The child queries pinned release 2026-09-23.1 with bbox/STAC pruning, filters subtype `road`, retains source attributes, and returns bounded JSON through a temporary file. Temporary output is removed after reading. No cloud credentials are required. The parent converts source, dependency, timeout, and ambiguous reader failures into `RoadDataError`.

The same service makes optional, explicit Overpass highway-way requests and rejects response remarks, incomplete geometry, and oversized responses. `analysis/roads.py::find_roads` validates/unions AOIs and enforces local bounds, clips centerlines to AOI interiors, excludes holes and boundary-only contacts, deduplicates source IDs, and measures WGS 84 geodesic lengths with pyproj. Overture and OSM remain independent reference datasets, avoiding misleading totals from overlapping sources. Access tags and scoped rules remain attached to original source IDs; linear fractions are not remapped after clipping.

`ui/roads.py` owns road controls, escaped name/class tooltips, visibility toggles, error reporting, source-separated downloads, and map overlays. `road_result` is bound to the AOI fingerprint and `road_error` stores the last reload error. Loading does not change building state, map mode, viewport, or map revision. Existing result groups plus road groups are passed as a list to `feature_group_to_add`, keeping the base map script/component identity stable. Roads never enter Leaflet.Draw's editable feature group. AOI changes/clear invalidate both road results and errors; panning and building edits retain them. Failed reloads retain the prior successful dataset with an explicit notice; optional OSM failures retain Overture with a warning. See `PROJECT.md` for limits and deferred scope.

## Manual pathway workspace

`core/pathways.py::validate_pathways(features, aois)` accepts a complete editor snapshot and returns canonical user-drawn LineString features with stable IDs, existing/planned status, unverified public access, and geodesic WGS 84 lengths. It rejects malformed/degenerate/self-crossing lines, reversed duplicates, repeated IDs, oversized snapshots, and routes outside the unioned AOI or crossing its holes. No metric measurements use geographic degrees. Sketch limits/semantics are in `PROJECT.md`.

`ui/pathways.py` owns `pathway_review`, `pathway_draft`, `pathway_edit_error`, `last_pathway_event`, and single-step `pathway_undo`. Invalid snapshots leave the accepted review and totals intact and disable export. Discard/undo increment the map revision to recover the editor from accepted state. All pathway state is cleared by AOI changes, not by building edits or source refreshes. `pathway_collection` exports only the separate user sketches; access rights are never inferred.

`ui/app.py` adds Pathways alongside AOI/Buildings modes. Only pathways enter Leaflet.Draw in this mode, which enables polyline drawing and disables polygon/rectangle drawing. Recovery metadata carries a separate pathway-editor flag and chooses pink dashed/solid styling. Created events attach UUIDs and provenance/status before the component serializes drawings. The Python callback routes pathway snapshots separately from AOIs/buildings. AOI boundaries and reviewed buildings are locked reference overlays, as are all source roads/OSM buildings; in other modes pathways are dynamic reference overlays. Data and viewport recovery remain in HTML to preserve the component script identity within a mode. Endpoint dragging/midpoint editing extends manual sketches; source import, snapping, and automatic routing are not implemented.

## FABDEM terrain workflow

`services/elevation.py` pins official Bristol FABDEM V1-2 URLs, resolving signed southwest-corner tile names with floor arithmetic (including southern/western coordinates) and 10-degree archive names. A half-cell lookup margin includes point-registered seam neighbors. `RemoteArchive` is a seekable HTTP range reader for `zipfile`; `RangeBudget` validates 206/Content-Range and response lengths, shares a byte/time budget across tiles, and rejects whole-archive responses. ZIP member reads are bounded before decompression and checked afterward. No archive is extracted to disk and no bulk elevation data enters the repository. Missing archives/members and invalid transfers raise `ElevationDataError`.

`analysis/elevation.py` validates AOIs before launching an isolated worker with a three-minute timeout. The worker uses Rasterio MemoryFiles to validate source grid/CRS, retain cropped native-grid windows, mosaic seams, mask samples by AOI pixel centers (including holes), and calculate unweighted valid-pixel statistics with explicit nodata coverage. No spatial metric is calculated from degrees. The float32 geographic GeoTIFF retains native spacing and EGM2008/unit/source/license tags. Only the display raster is reprojected to EPSG:3857 using nearest-neighbor sampling; the PNG's actual reprojected bounds are transformed back to geographic coordinates for Leaflet placement. JSON metadata records source tiles, AOI bounds, acquisition time, methods, limitations, and required FABDEM/Copernicus attribution. Temporary worker outputs are removed after bounded reads; raw source tiles are transient memory objects.

`analysis/contours.py` derives bounded linear isolines with ContourPy from the existing masked GeoTIFF. Geographic x/y coordinates refer to native pixel centers; masked quads are excluded (`corner_mask=False`) and generated lines are clipped to the exact AOI interior. There is no nodata filling, smoothing, or boundary extrapolation. Contours use multiples of the chosen interval relative to zero; every fifth is an index line. Auto spacing targets twelve levels with a 2 m minimum. The UI caches one interval/AOI result on the session's elevation data, so changes and existing loaded results need no new network request. Contour counts/vertices/levels are bounded as documented in `PROJECT.md`.

`ui/elevation.py` manages `elevation_result`/`elevation_error`, explicit analysis, coverage/source notices, statistics, contour interval/visibility/opacity, and GeoTIFF/GeoJSON/JSON downloads. Dynamic GeoJSON groups in the stable map's `terrain` pane replace the colored ImageOverlay. White halos keep brown lines visible over satellite imagery; heavier index lines get numeric labels, and hover tooltips show elevations. A layer-bound Leaflet control supplies the on-map legend and removes itself when the group is removed, avoiding duplicate/stale legends through toggles/reruns. Contours never enter editable feature groups. The worker's legacy PNG is no longer used by the map. Loading/visibility changes preserve AOI, buildings, OSM layers, roads, pathways, and viewport. AOI changes invalidate results; failed reloads retain the previous result with a visible notice. Source licensing is CC BY-NC-SA 4.0, requiring attribution/non-commercial use/share-alike; no commercial-use eligibility or public deployment is assumed. Native-grid precision is not survey accuracy. See `PROJECT.md` for limits and deferred analyses.
